# Domain language

## 정식 용어

### Hermes Discord Thread Attention

프로젝트 이름. Discord 쓰레드를 오래 보존하는 시스템이 아니라, 사용자가 선택한
열린 일을 적절한 시점에 다시 보게 하는 시스템이라는 뜻이다. 문서에서는
"retention bot"이나 "keepalive bot"을 프로젝트 이름처럼 쓰지 않는다.

### Stock-Hermes 플러그인 릴리스 (Stock-Hermes Plugin Release)

사용자가 공식 Hermes의 지원 버전을 수정하지 않고 이 플러그인 하나만 설치하는
배포 형태다. 개인 Hermes fork, install-time 코어 patch 또는 두 번째 release artifact를
뜻하지 않는다. 부족한 범용 호스트 기능을 Hermes upstream에 기여하는 것은 가능하지만,
그 기여가 공식 버전에 포함되기 전 로컬 코어 브랜치를 릴리스 의존성으로 부르지 않는다.

### 병합 전 프리뷰 설치 (Pre-merge Preview Install)

아직 공식 Hermes에 포함되지 않은 범용 호스트 계약과 플러그인을 함께 평가하는
비릴리스 설치 경로다. 검토된 PR 커밋을 별도 Hermes Git 브랜치에 고정 적용하고,
기본 라이브 프로필이 아닌 전용 `HERMES_HOME`에 플러그인을 비활성 설치한다.
Stock-Hermes 플러그인 릴리스나 라이브 배포를 뜻하지 않으며, 플러그인이 실행 중
Hermes 코어를 몰래 수정하는 방식도 아니다.

### 쓰레드 인벤토리 (Thread Inventory)

Hermes가 만들거나 참여한 쓰레드를 자동으로 기록하는 프로필 로컬 목록이다.
사용자가 명령을 입력하지 않아도 생성되며, 자동 발견의 기반이 된다.

### 과거 가져오기 (Historical Backfill)

기능을 처음 켤 때 Hermes의 영속 참여 기록에서 기존 쓰레드 메타데이터를 기간
제한 없이 인벤토리로 가져오는 절차와 그 항목을 뜻한다. 새 쓰레드의 노출을
막지 않도록 일일 다이제스트에는 단계적으로 섞는다.

### 접근 불가 상태 (Unreachable State)

삭제, 권한 상실 또는 조회 실패로 현재 유효한 Discord 링크를 확인할 수 없는
인벤토리 상태다. 기록을 버렸다는 뜻이 아니며, 정상 다이제스트 후보에서는
제외한다.

### 자동 발견 후보 (Discovery Candidate)

쓰레드 인벤토리 중 아직 사용자의 상호작용이 관찰되지 않았거나, 마지막 확인
기준점 뒤에 새 Hermes 활동이 생겨 다시 보여줄 필요가 있는 항목이다. 실제 미열람을
확정하는 용어가 아니다.

### 확인 기준점 (Acknowledgement Watermark)

사용자가 마지막으로 상호작용했을 때까지 수집기가 알고 있던 최신 Hermes 작업
메시지의 안정적인 ID와 시각이다. 그 뒤의 새 Hermes 활동을 기계적으로 구분하기
위한 경계이며, 사용자가 실제로 어디까지 읽었는지를 증명하지 않는다.

### 종료 상태 (Closed State)

`!c`/`!ㅊ`로 해당 쓰레드의 자동 발견과 재알림을 멈춘 상태다. Hermes가 새 메시지를
보내는 것만으로는 풀리지 않으며, 사용자의 일반 메시지나 유효한 확인·재알림 설정
명령으로 다시 열린다.

### 재알림 장부 (Reminder Ledger)

이미 본 쓰레드를 사용자가 정한 시점에 다시 보여 주기 위한 프로필 로컬 기록이다.
자동 인벤토리와 목적 및 상태를 분리한다.

### 전달 장부 (Delivery Outbox)

플러그인이 Discord로 보내야 할 확인·요약·다이제스트의 전달 의무와 시도 결과를
재시작 뒤에도 남기는 프로필 로컬 기록이다. 재알림 장부가 “언제 다시 볼지”를
다룬다면, 전달 장부는 “보내야 할 메시지가 실제로 전달됐는지”를 다룬다.

### 히스토리 제외 장부 (History Exclusion Ledger)

가로챈 제어 명령과 플러그인이 만든 고정 확인 메시지가 나중의 Discord 히스토리
복구나 문맥 수집을 통해 Hermes 세션·LLM 입력으로 들어가지 않도록 Discord 메시지
ID만 보존하는 프로필 로컬 기록이다. 메시지를 Discord에서 지우는 목록이 아니며,
명령 원문이나 확인 문구 본문을 저장하지 않는다.

### 제어 명령 (Control Command)

확인·종료·재알림 상태를 LLM 없이 변경하는 정확한 메시지다. `!`와 영문 한 글자를
기본으로 하며, 같은 두벌식 키의 한글 입력도 같은 명령으로 정규화한다. 실제 문법은
`SPEC.md`가 소유한다. 일반 프롬프트나 keepalive 잡담과는 다르다.

### 다시 볼 때가 됨 (Ready to Resurface)

자동 발견 정책에 걸렸거나 재알림 장부의 시각이 되어 일일 목록 후보가 된 상태다.
업무 마감일을 뜻하지 않는다.

### Discord 자동 보관 (Discord Auto-archive)

Discord가 비활성 쓰레드를 채널 목록에서 접는 수명주기 동작이다. 삭제가 아니며,
쓰레드 인벤토리나 재알림 장부의 항목도 없애지 않는다.

### 검토 다이제스트 (Review Digest)

자동 발견 후보와 선택적 재알림 후보를 제한된 수로 보여 주는 알림이다. 모든
쓰레드의 전체 내용을 매일 보고하는 것이 아니다.

## 관계

`Hermes 참여/과거 가져오기/확인 기준점 뒤 새 활동 → 쓰레드 인벤토리 → 자동 발견 후보 → 검토 다이제스트`

`제어 명령 → 재알림 장부 → 다시 볼 때가 됨 → 검토 다이제스트`

Discord 자동 보관은 두 흐름과 독립적이다. 재알림 장부는 "다시 볼 의무"를
다루고, 전달 장부는 "메시지가 실제 전달되었는가"를 다룬다. 히스토리 제외 장부는
이 두 상태와 별개로 "어떤 Discord 메시지를 Hermes 문맥에 넣지 않을지"를 다룬다.
