# Next gate

## 첫 구현 단위

기존 플러그인은 유지하고 새 기능만 기본 비활성으로 설치한다. 프로필의
`config.yaml`에 `thread_attention.enabled: true`와 다이제스트 채널을 한 번 저장하면
게이트웨이 재시작 뒤 계속 활성화되며, 기본 일정은 오전 9시 `Asia/Seoul`로
확정했다. 설정과 채널 검증을 통과하면 영속 활성화 ID와 과거 가져오기 스냅샷을
만들고, 실시간 수집을 먼저 연 뒤 과거분을 batch로 처리한다. 완료 트랜잭션에서
최초 요약 의무를 한 번 만들고 다이제스트를 열며, 중단되면 같은 스냅샷의 미완료
batch부터 이어 간다. 제품·실패·배포 설계와 소스 배치 관문은 닫혔다. 다음은 이
플러그인 Git 디렉토리에서 첫 구현 단위를 정하고, 필요한 범용 코어 연결부만 깨끗한
Hermes Agent 기능 worktree에서 병행하는 일이다.

결정할 항목:

1. 플러그인 코드를 검증 가능한 작은 모듈로 나눌 경계
2. 추가 전용 schema와 repository, 설정 parser를 첫 slice로 구현할 순서
3. 범용 Discord 히스토리 제외 연결부를 붙일 최소 Hermes Agent patch와 플러그인
   공개 인터페이스의 경계
4. 명령·수집·과거 가져오기·전달·다이제스트를 단계적으로 연결할 테스트 순서

## 관문 통과 조건

- 플러그인 코드는 이 `agent-extensions` Git 디렉토리에서, 범용 코어 변경만 깨끗한
  Hermes Agent 기능 worktree에서 개발한다.
- 첫 slice는 Discord 쓰기 없이 임시 `HERMES_HOME`의 설정·DB·멱등 재개를 테스트한다.
- 각 후속 slice가 일반 Hermes 메시지와 기존 관계 기능을 보존하는 자동 테스트를 둔다.
- 구현이 끝나기 전에는 라이브 설정, DB, 게이트웨이와 Discord를 변경하지 않는다.
